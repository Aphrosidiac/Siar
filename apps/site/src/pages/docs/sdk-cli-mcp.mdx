All three are generated from or built on the same OpenAPI contract as the API, so they cover the same {operations().length} operations and stay in step with it. They read the API key from `SIAR_API_KEY` and the API origin from `SIAR_API_URL` when set.

## TypeScript SDK

`@siar/sdk` has a typed method for every operation (`siar.post.create`, `siar.team.getList`, and so on), retries `429`, `5xx` and network errors on idempotent requests with exponential backoff, picks the right upload flow by size, pages through lists and verifies webhooks.

<CodeBlock lang="js" code={sdkSample} />

Errors are thrown as `SiarError` with `statusCode`, `message`, `issues` and `retryAfter`. Helpers worth knowing:

- `siar.paginate(operationId, params)`: async iterator over every page.
- `siar.uploads.fromFile(pathOrBlob)` and `siar.uploads.fromUrl(url)`.
- `siar.webhooks.constructEvent(rawBody, headers, secret)`: verify and parse; see [webhooks](/docs/webhooks).

## CLI

`@siar/cli` prints JSON on stdout and progress on stderr, so it composes with `jq`, shell scripts, CI and cron. Exit codes tell a script what happened: 0 ok, 2 usage, 3 auth, 4 not found, 5 validation, 6 rate limited, 7 server or network.
